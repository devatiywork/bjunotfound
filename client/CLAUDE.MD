# BjuNotFound Client - Инструкции для Claude

## Обзор проекта

**BjuNotFound** - менеджер питания и активности с трекингом КБЖУ (калории, белки, жиры, углеводы).

Современное React SPA-приложение на Vite, TypeScript и Tailwind CSS v4. Использует React 19 с SWC для быстрого обновления.

### Основной функционал

- **Аутентификация**: регистрация и авторизация пользователей
- **База продуктов**: добавление продуктов/блюд с расчетом КБЖУ
- **Дневник питания**: ежедневный трекинг приемов пищи
- **Цели**: установка и отслеживание целей по питанию и активности
- **Физические характеристики**: учет параметров пользователя (вес, рост и т.д.)

## Технологический стек

- **Сборщик**: Vite 7.2.4 с `@vitejs/plugin-react-swc`
- **Фреймворк**: React 19.2.0 с TypeScript 5.9.3
- **Стилизация**:
  - Tailwind CSS 4.1.18 (основа, v4 синтаксис через `@tailwindcss/vite`)
  - SCSS/Sass 1.97.1 для кастомных стилей
- **HTTP-клиент**: Axios 1.13.2 для API запросов
- **Роутинг**: React Router DOM 7.11.0 со стандартным роутингом
- **Иконки**: Lucide React 0.562.0 (tree-shakable, современные)
- **Типизация**: Строгий TypeScript с composite project configuration

## Ключевые архитектурные паттерны

### Конфигурация TypeScript

Проект использует TypeScript project references:

- `tsconfig.json` - Корневая конфигурация, ссылается на подконфиги
- `tsconfig.app.json` - Конфигурация кода приложения (src/)

**При добавлении новых конфигов всегда используй:**

- `moduleResolution: "bundler"`

### Архитектура проекта (Feature-Sliced Design)

Проект использует модульную архитектуру с разделением по фичам:

#### API слой (`src/api/`)

- Настройки и функции для работы с backend API
- URL бекенда выносится в `.env` файл (`VITE_API_URL`)
- Централизованная конфигурация Axios в `src/api/client.ts`

**JWT аутентификация (ВАЖНО):**

- Используются 2 токена:
  - **Refresh token**: долгоживущий, хранится в HTTP-only cookie
  - **Access token**: короткоживущий, хранится в **памяти** (не в localStorage!)
- Токены используются для всех запросов, кроме регистрации и авторизации
- При ошибке 401 автоматически обновляется access token и повторяется запрос
- Механизм перехвата запросов через Axios interceptors (`src/api/client.ts:22-97`)
- Очередь запросов во время обновления токена (`src/api/utils/queue.ts`)

**Ключевые файлы:**
- `src/api/client.ts:13-19` - Базовая конфигурация axios
- `src/api/client.ts:22-33` - Request interceptor (добавляет токен)
- `src/api/client.ts:38-97` - Response interceptor (обновление токена)
- `src/api/utils/token.ts` - Управление токенами в памяти
- `src/api/utils/queue.ts` - Очередь запросов

#### Страницы (`src/pages/`)

Каждая страница имеет единую структуру:

```
pages/
├── index.ts                 # Экспорт всех страниц
└── auth/                    # Пример страницы аутентификации
    ├── index.ts             # Экспорт страницы
    ├── ui/
    │   └── auth.tsx         # Компонент страницы
    ├── components/          # Компоненты только для этой страницы
    │   ├── index.ts         # Экспорт компонентов
    │   └── login-form/      # Каждый компонент имеет структуру как у страницы
    │       ├── index.ts
    │       └── ui/
    ├── types/               # TypeScript типы страницы
    ├── utils/               # Вспомогательные функции
    └── api/                 # API логика страницы
```

**Правила работы со страницами:**

- Все страницы экспортируются из `pages/index.ts`
- В `pages/` определяются глобальные общие функции для использования в компонентах
- Компоненты внутри страницы следуют той же структуре (ui/, types/, utils/, api/)
- ВСЕГДА читай существующий код перед созданием новой страницы, чтобы следовать паттерну

#### Переиспользуемые компоненты (`src/components/`)

- Компоненты, используемые на нескольких страницах
- Каждый компонент имеет свою папку с аналогичной структурой
- Общие UI-элементы (кнопки, поля ввода, карточки и т.д.)
- Существующие компоненты:
  - `theme-provider/` - Провайдер темной/светлой темы
  - `theme-toggle/` - Переключатель темы

#### Роутинг (`src/router/`)

- Конфигурация маршрутизации приложения через React Router DOM
- **Все маршруты SPA имеют префикс `/app`**
- `index.html` - статичный лендинг вне React со ссылками на регистрацию/авторизацию

**Текущие маршруты:**
- `/` → редирект на `/app/login`
- `/app/login` - Страница входа
- `/app/register` - Страница регистрации
- `/app/home` - Защищенная домашняя страница
- `/app/error` - Страница ошибки
- `/app` → редирект на `/app/login`
- `*` → редирект на `/app/error`

**Защита маршрутов (`src/router/ProtectedRoute.tsx`):**

- Все страницы, кроме регистрации и авторизации, защищены от неавторизованных пользователей
- При попытке доступа неавторизованного пользователя - редирект на страницу ошибки
- Страница ошибки содержит кнопки для перехода к регистрации/авторизации
- Реализуется через компонент `<ProtectedRoute>`

## Конвенции проекта

### React паттерны

- Используй возможности React 19 (без устаревших паттернов)
- Компоненты рендерятся в `<StrictMode>` - ожидай двойные вызовы в dev режиме
- **ВАЖНО**: React Compiler НЕ совместим с SWC плагином - избегай оптимизаций, специфичных для компилятора
- Функциональные компоненты с хуками
- Избегай избыточных абстракций

### Паттерны импортов

- Ассеты из `public/` используют абсолютные пути: `/vite.svg`
- Ассеты из `src/assets/` используют относительные импорты: `./assets/react.svg`
- Всегда указывай расширение `.ts`/`.tsx` в импортах: `import { router } from './router/index.tsx'`

### Подход к стилизации

- **Основа**: Tailwind utility классы напрямую в JSX
- Порядок импортов: импорт Tailwind CSS должен быть в главном CSS файле перед кастомными стилями
- SCSS только в исключительных случаях для специфичных стилей
- Нет CSS modules или styled-components

**Темная тема (КРИТИЧЕСКИ ВАЖНО):**

- Приложение поддерживает светлую и темную темы через `ThemeProvider` (`src/components/theme-provider/`)
- Тема переключается через класс `dark` на `<html>` элементе
- **ОБЯЗАТЕЛЬНО**: все новые стили должны поддерживать обе темы через Tailwind модификатор `dark:`
- Примеры правильных стилей:

  ```tsx
  // Фон
  className="bg-white dark:bg-gray-800"

  // Текст
  className="text-gray-900 dark:text-white"

  // Границы
  className="border-gray-300 dark:border-gray-600"

  // Поля ввода
  className="bg-white dark:bg-gray-700 text-gray-900 dark:text-white"
  ```

- Используй компонент `ThemeToggle` из `src/components/theme-toggle/` для переключения темы
- Тема сохраняется в localStorage и учитывает системные настройки

**Адаптивность и мобильная поддержка (КРИТИЧЕСКИ ВАЖНО):**

- Все страницы ОБЯЗАТЕЛЬНО должны иметь полную адаптивность
- Поддержка всех мобильных устройств (Android, iOS)
- Особое внимание к особенностям мобильных браузеров, в частности Safari:
  - Высота viewport (`100vh` vs `100dvh`)
  - Touch события и жесты
  - Safe area для notch/home indicator
  - Масштабирование и viewport meta tags
- Используй Tailwind breakpoints: `sm:`, `md:`, `lg:`, `xl:`, `2xl:`
- Mobile-first подход: начинай с мобильных стилей, затем добавляй breakpoints

## Инструкции для Claude при работе с проектом

### Общие правила

1. **ВСЕГДА читай файлы перед изменением**: Используй Read tool для понимания существующей структуры
2. **Следуй Feature-Sliced Design**: Новые фичи создавай в `src/pages/[feature]/` с правильной структурой
3. **Не создавай лишних файлов**: ВСЕГДА предпочитай редактирование существующих файлов
4. **Используй TodoWrite**: Для сложных задач планируй работу через TodoWrite tool
5. **Безопасность превыше всего**: Никогда не храни токены в localStorage, только в памяти

### При добавлении новой страницы

1. Прочитай существующую структуру страниц (`src/pages/login/`, `src/pages/home/`)
2. Создай структуру по паттерну:
   ```
   src/pages/[feature]/
   ├── index.ts
   └── ui/
       └── [feature].tsx
   ```
3. Экспортируй из `src/pages/index.ts`
4. Добавь маршрут в `src/router/index.tsx` с префиксом `/app`
5. Если нужна защита - оберни в `<ProtectedRoute>`
6. **ОБЯЗАТЕЛЬНО**: добавь поддержку темной темы (`dark:` классы)
7. **ОБЯЗАТЕЛЬНО**: сделай адаптивный дизайн (mobile-first)

### При работе с API

1. **ВСЕГДА используй `apiClient`** из `src/api/client.ts`
2. НЕ создавай новые экземпляры axios
3. Токены автоматически добавляются в заголовки
4. Обработка 401 происходит автоматически

```tsx
import { apiClient } from '@/api/client'

// GET
const response = await apiClient.get('/endpoint')

// POST
const response = await apiClient.post('/endpoint', data)
```

### При создании компонентов

1. Переиспользуемые компоненты → `src/components/[component]/`
2. Компоненты для конкретной страницы → `src/pages/[feature]/components/[component]/`
3. Структура компонента:
   ```
   [component]/
   ├── index.ts
   └── ui/
       └── [component].tsx
   ```
4. **ВСЕГДА**: поддержка темной темы
5. **ВСЕГДА**: адаптивный дизайн

### При стилизации

1. **Приоритет**: Tailwind utility классы
2. **ОБЯЗАТЕЛЬНО**: `dark:` модификатор для темной темы
3. **ОБЯЗАТЕЛЬНО**: responsive breakpoints (`sm:`, `md:`, etc.)
4. SCSS только для сложных случаев
5. Проверяй на мобильных устройствах (особенно Safari)

### Безопасность

1. Access tokens ТОЛЬКО в памяти (через `src/api/utils/token.ts`)
2. Refresh tokens ТОЛЬКО в HTTP-only cookies
3. Валидация пользовательского ввода
4. Защита от XSS через правильное использование React
5. HTTPS в production (настраивается на уровне деплоя)

### TypeScript

1. Строгая типизация - избегай `any`
2. Создавай типы в `[feature]/types/` для страничных типов
3. Используй интерфейсы для объектов
4. Type guards для проверок
5. `verbatimModuleSyntax: true` в tsconfig

### Комментарии в коде

- Код должен быть самодокументируемым
- Комментарии для сложной логики (особенно в API interceptors)
- JSDoc для публичных функций/компонентов
- Русские комментарии допустимы (как в существующем коде)

### Тестирование изменений

После изменений проверь:
1. `npm run build` - сборка без ошибок
2. `npm run lint` - линтинг проходит
3. Темная тема работает корректно
4. Мобильная версия работает
5. Аутентификация не сломалась (если трогал API)
