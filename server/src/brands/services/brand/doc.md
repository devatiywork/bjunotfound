# Brand Services - Документация

## CreateBrandService

**Файл:** `create-brand.service.ts`

**Назначение:** Создание нового бренда с проверкой дубликатов и автоматическим одобрением для администраторов

### Метод: `execute(dto, userId, isAdmin)`

**Описание:**
Создает новый бренд в системе. Если создатель - администратор, бренд сразу получает статус одобренного (`isApproved: true`). Если создатель - обычный пользователь, бренд требует модерации (`isApproved: false`).

**Параметры:**

- `dto` (CreateBrandDto) - Данные бренда (name, country?, photos?)
- `userId` (string) - ID создателя бренда
- `isAdmin` (boolean) - Флаг, является ли создатель администратором

**Возвращаемое значение:**
Объект созданного бренда с включенной информацией о создателе:

```typescript
{
  id: string;
  name: string;
  normalizedName: string;
  country: string | null;
  photos: string[];
  createdBy: string;
  isApproved: boolean;
  approvedBy: string | null;
  approvedAt: Date | null;
  rejectedAt: Date | null;
  rejectionReason: string | null;
  createdAt: Date;
  updatedAt: Date;
  creator: {
    id: string;
    email: string;
  };
}
```

**Исключения:**

- `BadRequestException` - если бренд с таким названием уже существует (проверяется через normalized_name)

**Особенности:**

- Использует `normalizeBrandName()` для генерации уникального ключа ("Danone" → "danone")
- Автоматически заполняет `approvedBy` и `approvedAt` для админов
- Пустая строна country сохраняется как null

**Пример использования:**

```typescript
const brand = await createBrandService.execute(
  { name: 'Dr. Oetker', country: 'Germany', photos: ['url1'] },
  'user-id',
  true, // Админ создает
);
// brand.isApproved === true, brand.approvedBy === 'user-id'
```

## UpdateBrandService

**Файл:** `update-brand.service.ts`

**Назначение:** Обновление данных существующего бренда (только для администраторов)

### Метод: `execute(id, dto)`

**Описание:**
Обновляет данные бренда. При изменении названия пересоздается `normalizedName` и проверяется уникальность.

**Параметры:**

- `id` (string) - ID бренда
- `dto` (UpdateBrandDto) - Обновляемые поля (name?, country?, photos?)

**Возвращаемое значение:**
Объект обновленного бренда с информацией о создателе и одобрителе

**Исключения:**

- `NotFoundException` - если бренд не найден
- `BadRequestException` - если новое название дублирует существующий бренд

**Особенности:**

- Регенерация `normalizedName` только если меняется название
- Проверка дубликатов исключает текущий бренд
- Частичное обновление (передаются только измененные поля)

**Пример использования:**

```typescript
const updated = await updateBrandService.execute('brand-id', {
  name: 'New Brand Name',
});
// Название изменено, normalizedName пересчитан
```

## DeleteBrandService

**Файл:** `delete-brand.service.ts`

**Назначение:** Удаление бренда с проверкой использования в продуктах

### Метод: `execute(id)`

**Описание:**
Удаляет бренд из системы. Запрещает удаление, если бренд используется хотя бы в одном продукте (глобальном или пользовательском).

**Параметры:**

- `id` (string) - ID бренда

**Возвращаемое значение:**

```typescript
{
  message: string; // "Бренд "{name}" успешно удален"
}
```

**Исключения:**

- `NotFoundException` - если бренд не найден
- `BadRequestException` - если бренд используется в продуктах (выводит количество продуктов)

**Особенности:**

- Подсчитывает использование через `_count` в обеих таблицах (productsGlobal + productsUser)
- Каскадное удаление НЕ применяется - защита от случайной потери данных
- Необходимо сначала удалить все продукты, использующие бренд

**Пример использования:**

```typescript
await deleteBrandService.execute('brand-id');
// BadRequestException: "Невозможно удалить бренд "Danone": используется в 15 продуктах"
```

## GetBrandService

**Файл:** `get-brand.service.ts`

**Назначение:** Получение бренда по ID с контролем доступа

### Метод: `execute(id, isAdmin, userId?)`

**Описание:**
Возвращает бренд с учетом прав доступа:

- Администратор видит любые бренды
- Создатель видит свои бренды (даже не одобренные)
- Остальные пользователи видят только одобренные

**Параметры:**

- `id` (string) - ID бренда
- `isAdmin` (boolean) - Флаг администратора
- `userId` (string, optional) - ID текущего пользователя

**Возвращаемое значение:**
Объект бренда с информацией о создателе, одобрителе и количестве продуктов

**Исключения:**

- `NotFoundException` - если бренд не найден или нет доступа к не одобренному бренду

**Особенности:**

- Двойная проверка: сначала существование, потом права доступа
- Возвращает 404 даже если бренд существует, но пользователь не имеет прав
- Включает подсчет использований в продуктах

**Пример использования:**

```typescript
const brand = await getBrandService.execute('brand-id', false, 'user-id');
// NotFoundException для не одобренного бренда, если пользователь не создатель
```

## ListBrandsService

**Файл:** `list-brands.service.ts`

**Назначение:** Получение списка всех брендов с фильтрацией по статусу одобрения и владению

### Метод: `execute(isAdmin, userId?)`

**Описание:**
Возвращает список брендов с умной фильтрацией:

- Администраторы видят все бренды
- Авторизованные пользователи видят одобренные бренды + свои неодобренные
- Неавторизованные пользователи видят только одобренные

**Параметры:**

- `isAdmin` (boolean) - Флаг администратора
- `userId` (string, optional) - ID текущего пользователя

**Возвращаемое значение:**
Массив брендов с информацией о создателе, одобрителе и количестве продуктов

**Особенности:**

- Используется OR-фильтрация для авторизованных пользователей: `isApproved = true OR createdBy = userId`
- Сортировка: сначала не одобренные (для админов), затем по дате создания (новые первые)
- Включает все связанные данные для полной картины
- Оптимизирован для отображения в списках

**Пример использования:**

```typescript
// Администратор
const brands = await listBrandsService.execute(true);
// Все бренды

// Авторизованный пользователь
const brands = await listBrandsService.execute(false, 'user-id');
// Одобренные + свои неодобренные

// Неавторизованный пользователь
const brands = await listBrandsService.execute(false);
// Только одобренные
```

## ListPendingBrandsService

**Файл:** `list-pending-brands.service.ts`

**Назначение:** Получение списка брендов, ожидающих модерации, с поиском потенциальных дубликатов

### Метод: `execute()`

**Описание:**
Возвращает бренды, которые не одобрены И не отклонены (ожидают решения администратора).
Для каждого бренда выполняется поиск потенциальных дубликатов среди всех брендов в системе.

**Параметры:**
Нет

**Возвращаемое значение:**
Массив брендов с информацией о создателе и потенциальных дубликатах:

```typescript
{
  id: string;
  name: string;
  normalizedName: string;
  country: string | null;
  photos: string[];
  createdBy: string;
  creator: { id: string; email: string };
  potentialDuplicates: Array<{
    id: string;
    name: string;
    normalizedName: string;
    isApproved: boolean;
    createdAt: Date;
    similarity: 'exact' | 'high' | 'medium';
    reason: string;
  }>;
}
```

**Алгоритм поиска дубликатов:**

1. **Exact (точное совпадение):** normalizedName полностью совпадает
2. **High (высокая схожесть):**
   - Одно название содержит другое как подстроку
   - Расстояние Левенштейна показывает схожесть ≥ 80%
3. **Medium (средняя схожесть):**
   - Схожесть 60-80% для коротких названий (≤15 символов)

**Особенности:**

- Фильтрация: `isApproved: false AND rejectedAt: null`
- Сортировка результатов: бренды с дубликатами первыми, затем по дате создания
- Дубликаты сортируются: exact → high → medium, одобренные бренды первыми
- Использует алгоритм Левенштейна для fuzzy matching

**Пример использования:**

```typescript
const pending = await listPendingBrandsService.execute();
// [
//   {
//     id: 'brand-1',
//     name: 'Данон',
//     potentialDuplicates: [
//       {
//         id: 'brand-2',
//         name: 'Danone',
//         isApproved: true,
//         similarity: 'high',
//         reason: 'Схожесть названий: 83%'
//       }
//     ]
//   }
// ]
```

## ListMyBrandsService

**Файл:** `list-my-brands.service.ts`

**Назначение:** Получение списка всех брендов текущего пользователя

### Метод: `execute(userId)`

**Описание:**
Возвращает все бренды, созданные пользователем, независимо от статуса (одобренные, на модерации, отклоненные).

**Параметры:**

- `userId` (string) - ID пользователя

**Возвращаемое значение:**
Массив брендов с информацией об одобрителе и количестве продуктов

**Особенности:**

- Фильтрация только по createdBy
- Сортировка: новые первые
- Включает rejectionReason для отклоненных
- Создатель не включается (это всегда текущий пользователь)

**Пример использования:**

```typescript
const myBrands = await listMyBrandsService.execute('user-id');
// Все статусы: одобренные, на модерации, отклоненные
```
