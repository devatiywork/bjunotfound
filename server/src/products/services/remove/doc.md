# Remove Product Service - Документация

## RemoveProductService

**Файл:** `remove-product.service.ts`

**Назначение:** Удаление продукта с проверкой прав доступа.

### Метод: `execute(id: string, userId: string, isAdmin: boolean)`

**Описание:**
Удаляет продукт из базы данных. Доступно только владельцу продукта или администратору. **Важно:** продукт не может быть удален, если используется в блюдах - сначала нужно удалить его из всех блюд.

**Параметры:**

- `id` (string) - UUID продукта для удаления
- `userId` (string) - ID текущего пользователя
- `isAdmin` (boolean) - Флаг администратора

**Возвращаемое значение:**
Объект с сообщением:

```typescript
{
  message: 'Продукт успешно удален';
}
```

**Логика работы:**

1. **Проверка существования:**
   - Ищет продукт по ID с включением связей dishIngredients
   - Загружает информацию о блюдах, где используется продукт
   - Выбрасывает `NotFoundException` если продукт не найден

2. **Проверка прав доступа:**
   - Если не админ И userId не совпадает с userId продукта
   - Выбрасывает `ForbiddenException`

3. **Проверка использования в блюдах:**
   - Если продукт используется хотя бы в одном блюде
   - Формирует список названий блюд через запятую
   - Выбрасывает `BadRequestException` с понятным сообщением и списком блюд

4. **Удаление продукта:**
   - Выполняет DELETE операцию (только если не используется в блюдах)
   - Prisma автоматически удаляет связанные данные (каскадное удаление):
     - Связи с тегами (ProductTag)
     - Персональные цены (UserProductPrice)

**Исключения:**

- `NotFoundException` - продукт с указанным ID не найден
- `ForbiddenException` - недостаточно прав для удаления (не владелец и не админ)
- `BadRequestException` - продукт используется в блюдах и не может быть удален

**Особенности:**

- **Каскадное удаление:** Автоматически очищаются все связанные данные
- **Права доступа:** Пользователь может удалять только свои продукты, админ - любые
- **Безопасность:** Нельзя удалить чужой продукт даже если знаешь ID
- **Необратимость:** Удаление необратимо (hard delete, не soft delete)

**Влияние на связанные данные:**

1. **UserProductPrice:**
   - Все персональные цены для этого продукта удаляются
   - Каскадное удаление (`onDelete: Cascade`)

2. **ProductTag:**
   - Все связи продукта с тегами удаляются
   - Сами теги остаются в БД

3. **DishIngredient:**
   - Ингредиенты с этим продуктом удаляются из блюд
   - Блюда могут стать невалидными (нужен пересчет КБЖУ)

**Пример использования:**

```typescript
// Удаление своего продукта
const result = await removeProductService.execute(
  'product-uuid',
  'user-uuid',
  false,
);

// Результат:
// { message: 'Продукт успешно удален' }
```

```typescript
// Админ удаляет чужой продукт
const result = await removeProductService.execute(
  'other-user-product-uuid',
  'admin-uuid',
  true, // isAdmin
);
```

```typescript
// Попытка удаления без прав
try {
  await removeProductService.execute(
    'other-user-product-uuid',
    'user-uuid',
    false,
  );
} catch (error) {
  // ForbiddenException: Недостаточно прав для удаления
}
```

```typescript
// Удаление несуществующего продукта
try {
  await removeProductService.execute('non-existent-uuid', 'user-uuid', false);
} catch (error) {
  // NotFoundException: Продукт не найден
}
```

**Рекомендации по использованию:**

1. **Перед удалением:** Проверить, используется ли продукт в активных блюдах
2. **Альтернатива:** Рассмотреть архивирование вместо удаления (soft delete)
3. **Для админов:** Удалять с осторожностью, особенно верифицированные продукты
4. **После удаления:** Если продукт использовался в блюдах, пересчитать КБЖУ этих блюд

**Важно:**

- Удаление продукта, используемого в блюдах, приведет к удалению ингредиента из блюда
- Это может сделать блюдо невалидным (например, если это был основной ингредиент)
- Рекомендуется предупреждать пользователя перед удалением, если продукт используется
