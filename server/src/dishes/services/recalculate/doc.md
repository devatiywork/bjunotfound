# Recalculate Dish Service - Документация

## RecalculateDishService

**Файл:** `recalculate-dish.service.ts`

**Назначение:** Пересчет КБЖУ и цены блюда при изменении данных продуктов.

### Метод: `execute(id: string, userId: string, isAdmin: boolean)`

**Описание:**
Пересчитывает КБЖУ и цену блюда на основе текущих данных продуктов. Используется когда обновились КБЖУ продуктов или цены пользователя, но состав ингредиентов блюда не изменился. Только создатель или админ могут пересчитать блюдо.

**Параметры:**

- `id` (string) - UUID блюда для пересчета
- `userId` (string) - ID текущего пользователя (используется для получения цен)
- `isAdmin` (boolean) - Является ли пользователь админом

**Возвращаемое значение:**
Обновленное блюдо со всеми связями (creator, ingredients, tags) и пересчитанными значениями КБЖУ и цены.

**Логика работы:**

1. **Проверка существования и прав:**
   - Ищет блюдо по ID с ингредиентами
   - Выбрасывает `NotFoundException` если не найдено
   - Проверяет права: только создатель или админ
   - Выбрасывает `ForbiddenException` если нет прав

2. **Получение данных продуктов:**
   - Извлекает productIds из ингредиентов
   - Загружает актуальные данные продуктов из БД

3. **Пересчет КБЖУ и цены:**
   - Вызывает CalculateNutritionService с текущими ингредиентами и userId
   - Рассчитывает значения на порцию

4. **Обновление в БД:**
   - Обновляет только поля КБЖУ и цены:
     - totalCalories, totalProteins, totalFats, totalCarbs
     - totalFiber, totalSugar
     - totalWeight
     - totalPrice
     - caloriesPerServing, proteinsPerServing, fatsPerServing, carbsPerServing
     - pricePerServing
   - НЕ обновляет ингредиенты, теги и другие поля

**Исключения:**

- `NotFoundException` - блюдо не найдено
- `ForbiddenException` - недостаточно прав

**Особенности:**

- **Персональный пересчет:** Использует цены текущего пользователя (userId), а не создателя
- **Актуальные данные:** Всегда берет свежие данные продуктов из БД
- **Безопасность:** Не меняет состав ингредиентов
- **Только КБЖУ и цена:** Остальные поля блюда остаются неизменными

**Когда использовать:**

1. **Обновились данные продуктов:** Админ изменил калорийность/БЖУ продукта
2. **Изменились персональные цены:** Пользователь обновил цены в UserProductPrice
3. **Периодический пересчет:** Плановое обновление данных
4. **После импорта:** Пересчет блюд после массового обновления продуктов

**Пример использования:**

```typescript
// Пересчет после обновления цен продуктов
const updated = await recalculateDishService.execute(
  'dish-uuid',
  'user-uuid',
  false,
);

// До пересчета:
// totalCalories: 450 (старые данные продуктов)
// totalPrice: 150.50 (старые цены)

// После пересчета:
// totalCalories: 465 (актуальные данные продуктов)
// totalPrice: 158.75 (актуальные цены пользователя)

// Админ пересчитывает блюдо после обновления БД продуктов
const updated = await recalculateDishService.execute(
  'any-dish-uuid',
  'admin-uuid',
  true,
);
```

**Сценарий массового пересчета:**

```typescript
// После обновления калорийности куриной грудки:
// 1. Админ обновил продукт: calories 165 → 170
// 2. Нужно пересчитать все блюда с этим продуктом

const dishesWithChicken = await prisma.dish.findMany({
  where: {
    ingredients: {
      some: { productId: 'chicken-breast-id' },
    },
  },
});

for (const dish of dishesWithChicken) {
  await recalculateDishService.execute(dish.id, dish.userId, true);
}
// Все блюда с курицей получили обновленные калории
```

**Применение:**

- Обновление данных после изменения продуктов
- Пересчет при обновлении персональных цен
- API endpoint для ручного пересчета
- Фоновые задачи по актуализации данных

**Отличие от UpdateDishService:**

- **RecalculateDishService:** Пересчитывает КБЖУ без изменения ингредиентов
- **UpdateDishService:** Изменяет ингредиенты и пересчитывает КБЖУ

**Важно:**

- Пересчет использует цены текущего пользователя (userId), не создателя
- Если у пользователя нет цен на ингредиенты - totalPrice станет null
- Состав ингредиентов НЕ изменяется, только их значения КБЖУ/цены
